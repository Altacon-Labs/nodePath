# 1. Product Overview

## Vision

To become the intelligence layer that enables blockchain ecosystems to understand, measure, and improve the journey from first user interaction to sustained onchain participation.

The platform connects fragmented Web2 and Web3 user activity into one measurable growth journey.

It answers the fundamental question every Web3 team struggles with:

> “What actually causes users to adopt, remain active, and create value onchain?”

---

# 2. The Problem

## Current Web3 Growth Problem

Web3 products have access to large amounts of blockchain data:

- Wallet addresses
- Transactions
- Smart contract interactions
- Token movements

However, they lack context.

They know:

> “A wallet interacted with our contract.”

But they do not know:

- Where the user came from
- What convinced them to try the product
- Which campaign influenced them
- Which community converted them
- Whether they are a real user or a bot
- Whether they will return
- Their long-term value

---

# Example Problem

A DeFi protocol launches a campaign.

Results:

- 100,000 website visitors
- 50,000 wallet connections
- 20,000 transactions

The team celebrates growth.

But after analysis:

- 70% came from incentive farming
- 60% never returned
- 40% were Sybil wallets
- Only 5,000 users became active participants

The problem:

The ecosystem measured activity.

Not adoption.

# Module 1:
# Web3 Multi-Touch Attribution Engine

## Purpose

Understand the complete user journey from discovery to blockchain action.

---

## Problem

Traditional analytics stops at:

- Website visit
- Click
- Signup

Web3 continues:

- Wallet connection
- Token transaction
- Contract interaction
- Protocol usage

---

## Solution

Track:

```
User sees campaign

↓

Visits website

↓

Connects wallet

↓

Completes transaction

↓

Returns and becomes active user
```

---

## Example Insight

Instead of:

“Twitter generated 50,000 visitors.”

The platform shows:

“Twitter campaign generated:

- 10,000 wallet connections
- 4,000 first transactions
- 1,500 retained users after 30 days”

---

## Metrics

- Acquisition source

- Retention by acquisition channel

# Module 3:
# Retention & Churn Prediction

## Purpose

Identify users likely to disappear.

---

## Example:

User behaviour:

Week 1:
10 transactions

Week 2:
5 transactions

Week 3:
1 transaction

Prediction:

High churn probability.

---

## Outputs:

- At-risk wallets
- Returning users
- Power users
- Dormant users

---

# Module 4:
# Sybil & Bot Detection Network

## Purpose

Separate real adoption from artificial activity.

---

## Detection Signals

- Wallet funding relationships
- Similar transaction timing
- Identical interaction patterns
- Cluster behaviour
- Multiple wallet ownership indicators

---

## Output:

Wallet classification:

```
Human User

High Confidence


Possible Sybil

Medium Confidence


Bot Cluster

High Confidence
```
